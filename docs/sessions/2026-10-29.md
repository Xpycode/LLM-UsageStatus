## Session 7 (continued) — Claude utilization-scale defect fix

**User's panel review (screenshots) caught a real defect:** the HUD showed "0% left · 5-hour
limit" while Claude's own page showed the current session at **2% used**. Root cause: the
endpoint's `utilization` is a **percentage** (2.0 = 2%), not a fraction — decoding it as a
fraction clamped the over-limit value to 100% used. Fixed in the decoder (normalize percent →
fraction, clamp at 100%; fixtures moved to the real scale; regression test added) — commit
a8a13f5, 134/134 tests green. Fresh Release build handed off (PID 43555, path + version
verified); its first live fetch logged `five_hour util=2% seven_day util=0%`, matching the
vendor page exactly.

**Also observed:** the Vibe glance line shows tokens only for this user — their store's
sessions carry either no model metadata or `zai-glm-5-3` (a non-Mistral model), so the
rate card correctly suppresses the cost part. This sharpens Backlog item 10's scope:
extending pricing beyond Mistral list prices and finding model names in the journal
records rather than only meta.json is the path to a money-first Vibe glance.
