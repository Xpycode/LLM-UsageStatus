## Progress

- **Panel jump (screenshots in `03_Screenshots/`, position by filename).** On every expand/collapse the
  content was shown for one frame centered in the *old* panel frame (collapse: dropped ~230 pt; expand:
  top clipped), then the panel snapped. Cause: SwiftUI re-laid out at once, but `UsagePanelController`
  resized the panel one main-queue hop later (GeometryReader → `DispatchQueue.main.async`).
  - First try (top-leading pinning only, build `04_Exports/0.3.0-panel-anchor-Debug`) did not fix it —
    the user still saw text jitter, which a screen recording could not catch.
  - Fix (`7af531a`): the hosting view resizes the document and panel from its own `layout()`, after
    SwiftUI's layout and before drawing, reading the ideal size as `intrinsicContentSize`
    (`sizingOptions = [.intrinsicContentSize]`); content stays pinned top-leading as a safeguard.
    Proven first in a headless probe (no window shown): one layout pass, top edge fixed, no extra pass;
    also confirmed `NSHostingView` and its clip view are flipped and that `fittingSize` is 0 once
    `sizingOptions` is empty. User confirmed: fixed.
- **Header (`9f8ede0`).** Under the centered, now underlined title the caption is just the spelled-out
  shortcut plus a borderless `gearshape` button (tooltip "Settings (Command-Comma)") that calls
  `openSettings()` through a new `UsageStatusView.onOpenSettings` closure. Layout chosen by the user
  (gear on the shortcut line). User confirmed it looks right.
- CHANGELOG 0.3.0 gained the gear (Added), header (Changed) and jump fix (Fixed); the plan's E1 entry
  notes the new build under test.
- Builds: three Debug builds, all zero warnings; tests not run locally (app-hosted) — CI runs on push.
