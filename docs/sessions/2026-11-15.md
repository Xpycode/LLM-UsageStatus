## Progress

- **Diagnosis.** The user saw no tooltip anywhere in the panel, not just over gauges, which ruled
  out nested `.help` (it could only hide the section tip over a gauge). The HUD is a
  `.nonactivatingPanel` (`UsagePanelController.swift:74`), so the app is almost never active, and
  AppKit tool tips (SwiftUI `.help`) only appear for the active app. User check: with Settings open
  (app active), a tooltip appeared — cause confirmed. Build 1's working section tooltip was most
  likely seen while the app happened to be active.
- **Fix — `Sources/Features/UsageStatus/Views/HoverTip.swift` (new).** `.hoverTip(_:)` modifier: a
  click-through `NSView` overlay (`hitTest` → nil) with an `.activeAlways` tracking area
  (entered/exited/moved) reports to `HoverTipController`, which shows one borderless,
  non-activating, mouse-ignoring tip panel (level floating + 1) after 0.6 s, placed below-right of
  the pointer and clamped to the screen. Overlapping areas: smallest area under the pointer wins
  (`HoverTipSelection.winner`); switching tips skips the delay; text updates live while shown,
  position stays put; a click/scroll (local event monitor) suppresses tips until the pointer leaves
  that area; `UsagePanelController.hide()` calls `dismissAll()`. VoiceOver gets the text as
  `accessibilityHint`. Env key `hoverTipsEnabled` (off in `SectionFixture.sectionView`, because
  `ImageRenderer` cannot draw the AppKit overlay). All four `.help` call sites replaced
  (`UsageStatusView.swift` gear, section, headline gauge, sub-gauge).
- **Duplicate bars removed (user choice).** Expanded view now shows bars only for meters without a
  same-label headline — `SectionVisibility.collapsedSecondaryMeters` renamed `secondaryMeters` and
  used for both states and the section tip; unused `visibleMeters` dropped. Credits, reset passes
  and reset-countdown rows unchanged. Help updated: `help-reading-the-panel.md`,
  `help-claude-code.md`, `help-codex.md`.
- **Tests.** New `Tests/Features/UsageStatus/HoverTipTests.swift` (winner selection, placement);
  `ProviderModelsTests` renamed test. `build-for-testing` green, zero Swift warnings; **tests not
  run** — the suite is app-hosted (needs go-ahead or CI).
